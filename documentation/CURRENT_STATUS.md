## Authority

Source code, migrations, and automated tests establish implementation facts. Accepted Architecture Decision Records (ADRs) in `documentation/decisions/` establish architectural direction; a newer ADR supersedes an earlier ADR only within its stated scope. When an accepted decision is not fully implemented, this document records the gap explicitly.

## Implemented

- **Desktop (`app/desktop`)**: The sole editor application. React and TypeScript renderer state stays behind a narrow Electron preload bridge; Electron main owns local media files, protected provider/browser runtime configuration, native capabilities, and timeline video assembly using local FFmpeg. It operates under single-user local-first principles ([ADR-0020](decisions/ADR-0020-single-user-local-first-architecture.md)).
- **Backend Service (`app/backend-service`)**: Spring Boot modular monolith and authoritative control plane. It manages Project/StoryVersion/Chapter/Scene/StoryBeat/AudioCue/VisualBeat metadata, admission, durable jobs, leases, and artifact metadata in PostgreSQL. The clean baseline is squashed into V1 through V7 and includes native cut snapshots, subtitle preferences, gated Chapter Analysis execution metadata, prompt settings, and the Antigravity execution mode ([DATABASE.md](architecture/DATABASE.md)). An installed database requires its own applied-history audit; inventory alone does not establish completed migration.
- **StoryBeat architecture and workstation UX**: The semantic hierarchy is `Project -> StoryVersion -> Chapter -> Scene -> StoryBeat -> {AudioCue[], VisualBeat[]}` ([ADR-0024](decisions/ADR-0024-storybeat-audio-visual-director-architecture.md)). StoryBeat, AudioCue, and VisualBeat persistence/read models and the Chapter Workspace grouping are implemented. VisualBeat approval remains decoupled from StoryBeat review.
- **Story analysis**: Vertex Gemini Chapter Analyze uses thinking level `HIGH` ([ADR-0022](decisions/ADR-0022-vertex-gemini-chapter-analysis.md)). Schema/prompt 1.1 requests explicit AudioCues; materialization validates anchors, speaker names and source revision before writes, then commits canon/story/cues and job completion in one Spring transaction. Cues begin DRAFT with no fabricated audio timing.
- **Generation service (`app/generation-service`)**: Domain-agnostic GPU execution plane ([ADR-0018](decisions/ADR-0018-backend-control-plane-and-domain-agnostic-gpu-execution-plane.md), [ADR-0019](decisions/ADR-0019-generation-service-light-ddd-hexagonal-structure.md)). It implements Compute Protocol v1 with capability-based machine authentication, a SQLite execution journal, durable submission checkpoints ([ADR-0021](decisions/ADR-0021-submission-checkpoint-and-worker-recovery-semantics.md)), and the worker SQLite `compute_event_outbox`.
- **Event-driven compute orchestration**: Worker state transitions are recorded with outbox events, delivered through signed callbacks, received idempotently in PostgreSQL, and finalized monotonically. A non-blocking scheduled reconciliation fallback handles ambiguous/lost callbacks. Backend generation updates are broadcast to Desktop through project-scoped SSE ([ADR-0025](decisions/ADR-0025-event-driven-compute-orchestration-and-reconciliation.md)).
- **Audio generation**: VieNeu TTS and WhisperX forced alignment are implemented through the generation service ([ADR-0023](decisions/ADR-0023-vieneu-remote-gpu-media-runtime.md)).
- **Image generation (PARTIAL)**: The current ComfyUI `image.generate:1.0` executor builds a text-to-image graph and does not consume input reference bytes. Character image conditioning is not implemented or runtime-proven ([ADR-0028](decisions/ADR-0028-image-generator-reference-only.md); [image workflow](workflows/IMAGE_GENERATION.md)).
- **Video generation & LTX Native AV cut-over**: Moving-video-first generation pipeline backed by LTX-2.5 (`video.generate`), shot sequencing, and multi-take models in V9 schema ([ADR-0026](decisions/ADR-0026-video-first-production.md), [ADR-0027](decisions/ADR-0027-shot-as-production-unit.md), [ADR-0032](decisions/ADR-0032-video-first-ltx-audio-native-production-runtime.md)). Schema 1.1 dispatch strictly adopts worker profile `ltx-2.5-22b-distilled-int8-native-av-v1` (revision `5e6e71018ee1756ed329b697a7b4aedc934dfce9`), with structured `dialogue[]` and `voiceReference` built from AudioCues. Active support is T2V, 1280x720/24 FPS/16:9; artifact conditioning, I2V, First/Last Frame and `AUDIO_FIRST` are blocked.
- **Aspect Ratio Normalization**: Normalized project ratios (`RATIO_16_9` to `16:9`) in SQL and preflight evaluation. Preflight fails closed prior to compute job dispatch when aspect ratios are unsupported.
- **Runtime Capability Truth**: Backend probes GPU worker `/v1/capabilities` and fails closed unless the exact task type, schema 1.1, model/revision and configured workflow profile are advertised and ready. T2V and Native AV readiness are derived from that profile.
- **Take Validation and Immutable Selection**: Terminal success, positive source duration, and technical validation PASS enforced before take selection ([ADR-0030](decisions/ADR-0030-take-selected-take-and-editing-director.md)). `SelectedTake` remains an immutable editing decision record.
- **Render Recovery & Project-Scoped Diagnostics**: Startup recovery handles multiple interrupted renders (`Tác vụ 1/N`), stage-aware resume/reconcile, per-job backend lease reclaim, checksum/version validation, explicit `USER_RETRY`, and local-first discard (`USER_CANCELLED`). Electron/PostgreSQL end-to-end recovery remains unverified in this environment. Job history and job indicators are scoped by `projectId`.
- **Backend-authoritative project continuation**: Project dashboard returns workflow progress derived from current backend source, canon, story, shot/take, selected-media and render state. Desktop merges it with local catalog metadata and falls back to Source when the backend is unavailable.
- **Compute target pinning**: Each compute `(taskId, attemptId)` has one durable target assignment. Submission records it before external I/O; reconcile and cancel use the same target and fail closed if it is unavailable.
- **Creator-first Production UX**: Compact production readiness strip, creator-friendly "Tạo các shot còn thiếu" action, expandable LTX technical details, and unblocked viewport scrolling for large shot boards.
- **Timeline composition and final render**: Electron FFmpeg assembles ordered selected take cuts with native source audio for `NATIVE_TAKE`, or narration-aligned media for explicit `EXTERNAL_NARRATION`. Native cuts use hard cuts; saved legacy profiles retain their composition behavior. The default is 24 FPS. Local fixture verification does not establish live GPU generation health ([editing pipeline](architecture/editing-pipeline.md)).
- **Subtitle display customization**: Project-scoped position, font, static presets, colors, size, weight and opacity are saved through backend APIs. Render carries the selected style into its request identity and immutable profile, with a fresh intent per deliberate export and frozen retries after ambiguous responses; Editor subtitle controls live in the Editor Inspector's Phụ đề tab and update the video preview immediately. The Render dialog keeps a summary and a jump to that tab; the Render screen reuses the controls at the actual output geometry. Legacy render snapshots preserve v1 pixels and fingerprint structure. Native word timing and standard Electron startup remain unverified.
- **Desktop UI Video-First Cut-Over**: Pruned obsolete still-image screens and legacy route aliases. Canonical workflow is anchored around `ChapterWorkspaceScreen`, `ProjectCanonScreen`, `AssetsScreen`, and `Editor`. Desktop video shotboard features real take generation, retake mutations, strategy updates, and take preview.

## Partial

- **Antigravity Chapter Analysis (PARTIAL — Desktop OAuth multi-account / not run against the provider)**: [ADR-0036](decisions/ADR-0036-desktop-google-oauth-multi-account-chapter-analysis.md) replaces the CLI adapter. Desktop implements Google OAuth (PKCE + loopback), per-account encrypted tokens, an `ANTIGRAVITY_API` runner and one parallel worker per account; Desktop unit tests pass with fakes and the Account screen renders (OAuth-not-configured state seen). Adapter revision 2 reuses a stored provider project ID or generates and persists a 9Router-style fallback locally, without a `loadCodeAssist` prerequisite; each analysis has its own session. Generated IDs are not proof of provider eligibility or live inference success. Backend `ANTIGRAVITY_API` mode, its schema (folded into the V1–V7 baseline), `credentialRef` claims and credential endpoints are written but NOT compiled or tested (no Java 25 toolchain available when written). The OAuth client must be supplied by the user (not committed). The provider request envelope, real login, real inference and multi-account isolation are unverified; the CLI mode remains only for history and queued CLI-frozen jobs need operator action. Antigravity Terms restrict third-party clients; this is experimental, not provider-approved.

- **Installation-wide Prompt Settings (PARTIAL — backend implemented, Desktop runtime unverified)**: [ADR-0035](decisions/ADR-0035-installation-wide-prompt-settings.md) (Proposed) and [the plan](product/PROMPT_SETTINGS_IMPLEMENTATION_PLAN.md). The working tree has V14, `GET/PUT /api/v1/settings/prompts`, `POST .../preview`, style/instruction resolution in storyboard, character, video and Chapter Analysis composers, admission-time freezing with settings-independent replay identity, and a Desktop Settings → Prompt tab. Verified by unit/contract tests and Desktop node tests plus a manual V14 run on PostgreSQL 16. **Not verified**: Spring/MyBatis/Flyway against PostgreSQL 18, Testcontainers integration tests, real Electron UI flow (runtime-verification blocked), provider output quality. Known residuals: the legacy non-frozen `VideoGenerationJobHandler` path still routes with `CINEMATIC`; `ComputeExecutionDispatcher` builds its `ChapterAnalysisJobHandler` without a frozen instruction; shot-take admission has no `expectedPromptRevision`; Desktop preview needs pasted ids for visual beat/shot targets.

- **Character consistency pack (PARTIAL)**: Typed visual profiles, policy/slot persistence, REST, and an eight-slot Desktop import/review/lock workflow exist in the current worktree. Installed-database acceptance and actual Electron flow remain unverified. The ComfyUI and LTX executors still do not condition outputs on these references; image/video identity consistency remains blocked until pinned GPU proof passes.
- **GPU residency arbitration**: `GpuResidencyManager` implements logical domain mutual exclusion (`COMFYUI_IMAGE`, `LTX_VIDEO`, `VIENEU`, `WHISPERX`), with `RuntimeProcessSupervisor` and `GpuVramProbe` wired into `bootstrap.py`. Active target is RTX 5090 (32GB VRAM); production strictness and full Windows worker validation remain in progress.
- **Native subtitle timing**: The native renderer accepts observed take word timings, but current result finalization and snapshot insertion do not produce/populate them. Styling does not fabricate these timings. Native takes without observations have no timed captions; legacy narration alignment is exposed for Editor playback.
- **Native Editor playback and multiple shots**: The backend/native renderer carries distinct shot/take cuts, but the Editor still identifies selections by VisualBeat and mutes preview video while loading legacy narration. Native preview audio and multiple cuts on one beat remain PARTIAL; local final-render fixtures do not verify that Editor workflow ([review evidence](reviews/2026-10-12-review-cleanup.md)).
- **Canonical StoryBeat materialization**: StoryBeat/AudioCue/VisualBeat domain boundaries and grouped reads are implemented, but nullable legacy/manual VisualBeat rows remain supported and not every existing analysis/manual row is proven to be attached to a StoryBeat.
- **Full remediation E2E**: Targeted unit and contract checks cover the new boundaries, but the full creator journey and runtime failure-mode flow still require an Electron + PostgreSQL environment.

## Target / Active Cut-Over

- **Video-First Production**: Shot/Take generation and selected-cut rendering are implemented foundations. Retention planning and feedback automation remain partial or deferred; the full target pipeline in ADR-0026 through ADR-0032 is not a claim that every stage is implemented.
- **Generation Router & Extended Video Strategies**: Strategy types and planning rules cover T2V, I2V and First/Last Frame, but the active pinned runtime admits only T2V. I2V/reference conditioning and all extended strategies require capability and runtime proof before admission ([ADR-0029](decisions/ADR-0029-generation-router-and-video-strategies.md)).
- **Editing Decision List & Final Multi-Track Assembly**: Advanced EDL export and non-linear transitions compilation ([ADR-0030](decisions/ADR-0030-take-selected-take-and-editing-director.md)).

## Deferred / Not Implemented

- **Automated YouTube decision loop**: Retention feedback loop operates in human-in-the-loop recommendation mode; fully automated strategy re-tuning without human approval remains deferred ([ADR-0031](decisions/ADR-0031-retention-driven-narrative-planning.md)).
- **Advanced identity verification**: Real-person biometric embeddings and automated consent verification remain deferred.

## Known Drift

- **Remote GPU deployment**: `deploy/remote-gpu/docker-compose.yml` reflects a legacy Linux Docker prototype, while the active target execution environment is a disposable Windows RTX 5090 (32GB VRAM) workstation with RTX 3090 (24GB VRAM) as benchmark baseline (see [REMOTE_GPU_RUNTIME.md](operations/REMOTE_GPU_RUNTIME.md)).
- **Environment configuration**: Template defaults in `app/generation-service/.env.example` require alignment with disposable workstation setup scripts.
- **Legacy VisualBeat rows**: Nullable `visual_beats.story_beat_id` is an intentional compatibility path, not evidence that the canonical hierarchy is the old Scene-to-VisualBeat model.
