# NarrativeX Compute Protocol v1

## Status

Target design for the compute execution-plane migration. This document defines the boundary;
implementation status must be recorded separately as each migration phase lands.

## Boundary

The backend is the control plane. It owns domain interpretation, admission, entitlement and
capacity checks, `GenerationJob`, `StageAttempt`, `ProviderOperation`, retries, reconciliation,
idempotency, outbox state, artifact publication, and all NarrativeX database writes.

`gpu-worker` is a domain-agnostic execution plane. It accepts a fully materialized compute task,
invokes an executor, stages output artifacts, and reports observations. It must not:

- receive or infer `Project`, `Chapter`, `Scene`, `VisualBeat`, character, workspace, or user IDs;
- connect to the NarrativeX PostgreSQL database;
- resolve NarrativeX domain records or construct domain output;
- decide retry, quota, entitlement, job completion, or provider reconciliation policy;
- accept or return absolute host filesystem paths.

Local RTX 4060 and remote GPU deployments implement the same versioned HTTP contract. Backend
target configuration changes endpoint, credentials, capabilities, and scheduling weight without
changing a domain use case.

## Concepts

### ComputeTask

A single immutable execution request. A retry is a new `attemptId`; replay of the same attempt is
idempotent. The backend persists its reservation/outbox state before submission.

```json
{
  "protocolVersion": "1.0",
  "taskId": "0199b861-cc3c-7a8e-a915-e5dbff3af7aa",
  "attemptId": "0199b862-1025-78be-bd71-c6969b74ab71",
  "idempotencyKey": "compute:0199b861-cc3c-7a8e-a915-e5dbff3af7aa:1",
  "requestFingerprint": "0d3c8f5d67c48b0889828cc22b2d51cd9785f51b788350134209d1be1b411285",
  "task": {
    "type": "audio.synthesize",
    "schemaVersion": "1.0"
  },
  "model": {
    "executor": "voicestudio",
    "model": "vi-profile",
    "revision": "0.5.2"
  },
  "constraints": {
    "deadline": "2026-09-14T12:00:00Z",
    "maxRuntimeSeconds": 900
  },
  "inputs": {
    "script": "Untrusted story text is data, never worker instructions.",
    "voice": {"kind": "catalog", "value": "vi_female_01"},
    "format": {"container": "wav", "sampleRateHz": 48000, "channels": 1}
  },
  "artifacts": []
}
```

Rules:

- UUIDs are opaque protocol identifiers generated by the backend; they are not domain IDs.
- `requestFingerprint` is SHA-256 over UTF-8 canonical JSON (`sort_keys=true`, no insignificant
  whitespace) containing exactly `protocolVersion`, `task`, `model`, `inputs`, and each artifact's
  `artifactId`, `role`, `mediaType`, `sizeBytes`, and `sha256`. Protocol/task/attempt/idempotency IDs,
  constraints, and the entire expiring `access` descriptor are excluded. The same semantic compute
  request therefore keeps its fingerprint across attempts and refreshed artifact capabilities.
- `task.type` selects a versioned input/output schema from the executor registry. Unknown fields
  are rejected by default; an unrestricted `metadata` bag is deliberately absent.
- Story text, prompts, references, and model output remain untrusted data. Executors must treat
  them as typed input and must not interpret them as control-plane instructions.
- Model selection is explicit and immutable for an attempt. A target may reject unsupported
  executor/model/revision combinations but may not silently substitute another model.

Initial task types are `audio.synthesize`, `audio.align`, `image.generate`, and `media.validate`.
Add a task type only with schemas, deterministic validation, capability advertisement, tests, and
documented artifact behavior. FFmpeg GPU work can later use `media.transcode`; chapter analysis is
not an initial GPU task and remains backend-owned until a domain-neutral compute boundary exists.

### ArtifactRef

```json
{
  "artifactId": "0199b86a-6db8-75b8-bd98-78442a0177dd",
  "role": "voice-reference",
  "mediaType": "audio/wav",
  "sizeBytes": 382144,
  "sha256": "250c...64-lowercase-hex-characters...c945",
  "access": {
    "method": "GET",
    "url": "https://artifact-gateway.example/opaque-capability",
    "expiresAt": "2026-09-14T12:15:00Z",
    "headers": {}
  }
}
```

The reference identifies bytes, integrity, purpose, and a time-bounded access capability. The URL
is transport data and is excluded from stable fingerprints. Logs must redact URLs and authorization
headers. Output slots use the same shape with backend-issued `PUT` access. A worker uploads to a
staging capability, verifies the byte count and digest locally, and reports the resulting reference;
the backend verifies and atomically publishes it before completing domain state.

Local deployments may implement the artifact gateway over loopback, but the wire contract remains
an opaque URL/capability. `file://`, drive letters, UNC paths, project-relative storage keys, and
host absolute paths are invalid protocol values.

### ComputeResult

```json
{
  "protocolVersion": "1.0",
  "taskId": "0199b861-cc3c-7a8e-a915-e5dbff3af7aa",
  "attemptId": "0199b862-1025-78be-bd71-c6969b74ab71",
  "state": "SUCCEEDED",
  "sequence": 7,
  "observedAt": "2026-09-14T11:42:31Z",
  "executionHandle": "opaque-to-backend-and-logs",
  "outputs": [],
  "metrics": {
    "runtimeMs": 18321,
    "gpuTimeMs": 17104,
    "peakVramBytes": 6442450944
  }
}
```

Terminal failure uses a bounded, non-sensitive error contract:

```json
{
  "state": "FAILED",
  "error": {
    "code": "INVALID_INPUT",
    "category": "PERMANENT",
    "message": "Input audio is not a valid WAV stream",
    "retryAfterSeconds": null,
    "details": {}
  }
}
```

Allowed categories are `PERMANENT`, `TRANSIENT`, `CAPACITY`, and `CANCELED`. They are observations,
not retry decisions. Backend policy chooses whether and when to create another attempt. Error
messages and details must not contain prompts, secrets, signed URLs, provider response bodies, or
local paths.

## HTTP contract

All media types are `application/vnd.narrativex.compute-v1+json`.

| Method | Path | Purpose |
|---|---|---|
| `GET` | `/v1/capabilities` | Worker identity, protocol versions, executors/models, task schemas, limits and health summary |
| `POST` | `/v1/tasks` | Submit an immutable attempt; return `202 Accepted` or the stored replay response |
| `GET` | `/v1/tasks/{taskId}/attempts/{attemptId}` | Reconcile after timeout or ambiguous submission |
| `POST` | `/v1/tasks/{taskId}/attempts/{attemptId}:cancel` | Request cooperative cancellation; idempotent |
| `POST` | backend callback URL `/internal/v1/compute-events` | Deliver sequenced observations when configured |

`POST /v1/tasks` must return the same acceptance/result for the same `attemptId`, idempotency key,
and fingerprint. Reusing one of those identifiers with a different fingerprint returns `409
Conflict`. Unsupported protocol/task/model combinations return `422`; temporary capacity returns
`429` with `Retry-After`; authentication/authorization uses `401`/`403` without revealing target
configuration.

Callbacks are an optimization, not the source of truth. Backend reconciliation through `GET`
closes lost-callback and ambiguous-submit gaps. Every observation carries a monotonically increasing
`sequence`; duplicates and older sequences are accepted as no-ops. The minimal execution states are:

```text
ACCEPTED -> RUNNING -> SUCCEEDED
                    -> FAILED
                    -> CANCELED
```

Loss of acknowledgement or transport does not itself produce an execution state. The backend maps
that ambiguity to durable `ProviderOperation.UNKNOWN` and reconciles before resubmitting. A worker
restart must recover accepted/running attempts from its own execution journal; that journal is
execution-local and contains no NarrativeX domain data.

## Security and operational requirements

- Authenticate each target using a separate machine credential; prefer mTLS for remote targets and
  bind local workers to loopback/private interfaces. Rotate credentials independently of users.
- Authorize callback events to one target identity and reject task/attempt mismatches.
- Never pass `DATABASE_URL` or NarrativeX service credentials to `gpu-worker`.
- Enforce request size, artifact size, media type, checksum, decompression, runtime, output count,
  concurrency, and model allow-list limits before execution.
- Redact prompt/input content, signed artifact URLs, voice references, provider bodies, and execution
  handles from logs. Correlate by `taskId` and `attemptId` only.
- Capability discovery is cached for routing but cannot override the backend model/target registry.
- Readiness means the configured executor/model can accept work; fake executors are test-only and
  must never report production readiness.

## Ownership mapping

| Concern | Backend control plane | GPU execution plane |
|---|---|---|
| Domain context and materialization | Owns | Forbidden |
| Admission, quota, entitlement, abuse checks | Owns | Enforces only local safety/capacity limits |
| Job/attempt/provider lifecycle | Owns durable truth | Reports execution observations |
| Retry and `UNKNOWN` reconciliation | Decides and persists | Returns idempotent status by attempt |
| Model and target registry | Owns desired configuration | Advertises actual capabilities |
| Artifact identity/publication | Coordinates and verifies | Downloads/uploads through capabilities |
| Provider/engine SDKs | Forbidden from domain modules | Executor adapters own them |
| NarrativeX PostgreSQL | Owns | Forbidden |

## Compatibility

Minor additions may add optional fields or task schemas without changing existing semantics. Any
renamed field, changed state meaning, changed fingerprint rule, or changed artifact behavior requires
a new major media type and a parallel compatibility window. Backend and worker contract tests use a
shared checked-in JSON Schema/OpenAPI source and golden examples.
